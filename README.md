# Book Journal
Задеплоен [сюда](https://book-journal.quietpage.workers.dev/)

Приватный минималистичный читательский дневник (веб). Суть — **память о прочитанном**,
а не каталог и не соцсеть.

**Принцип-фильтр:** каждая фича либо помогает *поймать момент*, либо *вернуть его потом*.
Иначе — не делаем.

---

## 1. Продуктовые решения

- Статусы: **хочу / читаю / прочитал** + заметка «почему добавил».
- **Сессии чтения** (поддержка перечитывания), дневник (мысль/цитата), финальный отзыв
  с приватной оценкой.
- У любой записи (мысль или цитата) можно указать страницу.
- **«Возврат»:** в библиотеке всплывает карточка со свежей цитатой и ведёт обратно в книгу.
- Ввод — **только текст**.
- **Без регистрации и без аккаунтов** — личный дневник никуда не отправляется.
- Никаких лент, рейтингов, геймификации, давящих напоминаний.

## 2. Архитектура

- **Толстый клиент:** TypeScript + Vue 3 + Vite; личные данные — в **IndexedDB** браузера
  (Dexie, база `myBookShelf` в `data/db.ts`). Своего сервера нет.
- Следствие приватности: данные привязаны к конкретному браузеру на конкретном
  устройстве — в другом браузере библиотека будет пустой.
- Внешние сервисы используются только на экране «Добавить» и только для поиска:
  - **OpenLibrary** — поиск книг и обложки;
  - **Google Translate (неофициальный gtx-endpoint)** — перевод запросов и названий.
  Наружу уходит только поисковый запрос; дневник, отзывы и оценки — никогда.
  Обложка выбранной книги скачивается **один раз** и хранится в IndexedDB как data-URL,
  поэтому показ библиотеки не зависит от внешних серверов.

## 3. Стек и запуск

| | |
|---|---|
| Сборщик | Vite 5 |
| UI | Vue 3 (`<script setup lang="ts">`) + TypeScript |
| Состояние | Pinia (сторы `journal`, `modals`) |
| Хранение | IndexedDB через Dexie 4 (`data/db.ts`) |
| Роутинг | vue-router 4 |
| Внешние API | openlibrary.org (поиск), covers.openlibrary.org (обложки), translate.googleapis.com (переводы) |
| Стили | кастомный CSS (`src/index.css`) поверх Bootstrap 5 (только CSS, без JS) |

```bash
npm install
npm run dev      # дев-сервер: http://localhost:5173
npm run build    # прод-сборка: vue-tsc --noEmit + vite build → dist/
npm run preview  # локальный предпросмотр прод-сборки
npm run lint     # только проверка типов (vue-tsc --noEmit)
```

## 4. Архитектура клиента в двух словах

```
                       ┌─────────────────────────────┐
   UI-состояние   ───► │  stores/modals.ts            │  какие модалки открыты
   (модалки)           └─────────────────────────────┘
                                  ▲
   Экраны/компоненты ─────────────┤ читают данные и вызывают действия
   (pages/, components/)          ▼
                       ┌─────────────────────────────┐
   Данные         ───► │  stores/journal.ts           │  ◄── ЕДИНСТВЕННАЯ точка
   (книги/записи)      │  кэш книг/записей в памяти    │      работы с хранилищем
                       │  + действия add/update/get    │
                       └──────────────┬──────────────┘
                                      │ фоновая запись (put) / загрузка (init)
                                      ▼
                       ┌─────────────────────────────┐
   Хранение       ───► │  data/db.ts (Dexie)          │  IndexedDB «myBookShelf»
                       └─────────────────────────────┘

   Внешний мир    ───► │  data/catalog.ts             │  OpenLibrary + переводчик
   (только поиск)      │  searchCatalog / downloadCover│  (используется экраном «Добавить»)
                       └─────────────────────────────┘
```

Главный принцип: **компоненты не знают, откуда берутся данные**. Они только вызывают
методы стора `useJournal()` (`addBook`, `addEntry`, `getBook`, …). Так переезд
с in-memory на IndexedDB затронул **один файл** — `stores/journal.ts` — а экраны
не изменились.

    │   ├── Sidebar.vue      левое меню: навигация (SVG-иконки), статусы со счётчиками
    │   ├── TopBar.vue       верх: поиск по библиотеке, «Записать мысль», «Добавить книгу»
    │   ├── HomeRedirect.vue редирект «/» → последняя книга со статусом «Читаю» (или библиотека)
    │   ├── Cover.vue        «корешок» книги: CSS-градиент, внешний URL или data-URL из базы
    │   ├── EmptyState.vue   единое оформление пустых состояний (слот #action)
    │   ├── StatusSelect.vue дропдаун смены статуса

    │       ├── QuickNoteModal.vue   «Записать мысль» (мысль/цитата, страница — опционально)
    │       └── ReviewModal.vue      «Впечатление»: сохранить отзыв или «Завершить без отзыва»
    │
    └── pages/               ОДИН файл = ОДИН экран (маршрут)
        ├── LibraryPage.vue  «/library»   полки по статусам + карточка-«возврат» + фильтр поиска
        ├── FeedPage.vue     «/feed»      лента всех записей
        ├── BookPage.vue     «/book/:id»  карточка книги + дневник + сессии + «Завершить книгу»

**Маршруты:** «/» — это `HomeRedirect`: открывает последнюю книгу, помеченную «Читаю»
(по самой свежей сессии), иначе — библиотеку `/library`.

## 6. Куда добавлять логику

| Что нужно сделать | Куда писать |
|---|---|
| Вид экрана, вёрстка, тексты | соответствующий файл в `pages/` или `components/` |
| Локальное состояние экрана (поля формы, табы) | `ref`/`computed` прямо в компоненте (как в `AddBookPage.vue`) |
| Работа с данными (книги, записи) | `stores/journal.ts` — добавить действие в стор |
| Открыть/закрыть модалку из любого места | `stores/modals.ts` (`openNote`, `openReview`, …) |
| Новый тип/поле сущности | `types.ts` (затем форма + отображение) |
| Новая таблица/индекс в базе | `data/db.ts` — схема Dexie (не забыть поднять версию: `this.version(n)`) |
| Определение языка, перевод | `utils/language_perform.ts` |
| Источник каталога (замена OpenLibrary на свой сервер) | `data/catalog.ts` — заменить тела `searchCatalog`/`downloadCover` |

**Правило:** любая операция над данными проходит через `useJournal()`, а не через
прямые обращения к хранилищу/сети внутри экранов.

### Как устроено хранение

Схема «кэш в памяти + фоновая запись на диск»:

1. `data/db.ts` — Dexie-класс `MyBookShelf`: база `myBookShelf`, таблицы `books`
   и `entries` (первичный ключ `id`, генерируется на клиенте через `crypto.randomUUID()`).
2. `stores/journal.ts` держит реактивный кэш (`ref([])`). Изменение сразу применяется
   к кэшу (UI обновляется мгновенно), а в IndexedDB уходит фоном через `put` (upsert).
3. Перед записью объект очищается от Vue-прокси (`snapshot` = JSON-копия).
4. `journal.init()` загружает всё из базы в кэш; вызывается в `main.ts` до `mount`.
5. Обложки хранятся внутри книги как data-URL (base64, ~15–50 КБ на книгу) —
   библиотека полностью автономна и работает офлайн.

### Как устроен поиск по каталогу («Добавить»)

1. Запрос уходит в OpenLibrary (до 100 результатов). Русский запрос дублируется
   английским переводом, результаты склеиваются без дублей.
2. Выдача листается по 10; английские названия подписываются русским переводом
   («Title (Перевод)») — переводятся только видимые страницы, лениво.
3. При добавлении: обложка скачивается в data-URL, перевод названия сохраняется
   в `Book.titleRu`; дальше навигация по статусу — «хочу» → библиотека,
   «читаю» → книга, «прочитал» → книга + модалка отзыва.

### Поиск по библиотеке

Строка в TopBar пишет в `journal.librarySearch`, фильтр применяет `LibraryPage`:
русский запрос ищет по `title` и `titleRu`, английский — только по `title`.

## 7. Рецепты

- **Новое поле книги:** `types.ts` → `AddBookPage.vue` (ввод) → `BookPage.vue` (показ).
- **Новый экран:** `pages/NewPage.vue` → маршрут в `router.ts` (ребёнком Layout) →
  при необходимости пункт в `Sidebar.vue`.
- **Новая модалка:** состояние в `stores/modals.ts` → `components/modals/XxxModal.vue`
  (разметка `.modal` + `.bj-sheet` / `.bj-sheet-dialog`, `Teleport to="body"`) →
  отрендерить в `Layout.vue`.
- **Новый статус:** `types.ts` → расширить `BookStatus`, `STATUS_META`, `STATUS_ORDER` —
  сайдбар, полки и сегмент-контролы подхватят автоматически.

### Сессии чтения и завершение книги

Статус меняется через `setStatus(id, status)` из стора (не `updateBook`): «Читаю» открывает
новую `ReadingSession` (`startedAt`), любой другой статус закрывает текущую (`endedAt`).
Открытая сессия = «идёт сейчас», последняя закрытая = «прошлый раз». Модель —
`Book.sessions` в `types.ts`.

Завершение — через кнопку **«Завершить книгу»** на странице книги (видна при открытой
сессии): она открывает модалку «Впечатление», где можно сохранить отзыв с оценкой
(книга завершается) или нажать «Завершить без отзыва».

**Записи привязаны к чтению:** кнопка «+ Записать мысль» в карточке видна в пустом
дневнике при статусе «Читаю»; глобальная «Записать мысль» (верхняя панель) предлагает
выбрать книгу из читаемых сейчас. При добавлении книги статус по умолчанию — «Хочу читать».

## 8. Соглашения по стилям

- **Весь дизайн** — в `src/index.css`. Дизайн-токены (цвета, шрифты) — в `:root`
  (`--paper`, `--ink`, `--accent`, `--serif`, `--sans`, …).
- Bootstrap подключён только как CSS (reset + база модалок). Конфликтующие имена
  переименованы: **`.btn` → `.bj-btn`**, **`.nav` → `.bj-nav`**; модалки — **`.bj-sheet` /
  `.bj-sheet-dialog`**. Не вводите классы `btn`/`nav`/`modal` в кастомном CSS.
- Внутри `.modal-content` (flex-контейнер Bootstrap) блочные элементы растягиваются —
  компактным плашкам нужен `align-self: flex-start` (см. `.bj-sheet .bk`).
- Модалки и дропдауны собраны вручную на bootstrap-классах (`.modal.show` + backdrop,
  `.dropdown-menu.show`) — JS-часть Bootstrap не используется.
- Кнопки — нативный `<button class="bj-btn">` (варианты `ghost`, `wide`; есть стиль
  `:disabled`).
- Поле + кнопка в один ряд — обёртка `.fieldrow` (выравнивает высоты и снимает
  внешний отступ у `.field`).
- Пагинация выдачи — `.pager`; лоадер поиска — `.bookload` (книжка с перелистывающимися
  страницами, чистый CSS).
- `Cover` рендерится как `<span>` — в новых контекстах задавайте ему размеры и
  `display: block` / `flex: none` (инлайновому элементу ширина не применяется).
- Ссылки-карточки (`.bookrow`, `.tile`, `.recall`, навигация) — `<RouterLink>`;
  подчёркивание ссылок сброшено глобально.

> Известное ограничение макета: сайдбар (268px) не сворачивается на узких экранах —
> адаптив есть только для полок/сеток.
